# Contributing to openclaw-watchdog

Thanks for your interest in contributing!

## Reporting Issues

- Check existing issues first
- Include your OS, OpenClaw version, and relevant logs
- For security issues, email directly (don't open public issues)

## Pull Requests

1. Fork the repo
2. Create a feature branch (`git checkout -b feature/amazing-feature`)
3. Make your changes
4. Test on at least one platform (macOS or Linux)
5. Submit a PR with a clear description

## Code Style

- Bash scripts: Use `shellcheck` for linting
- Keep it simple — this is meant to be auditable
- Comment non-obvious logic
- Test your changes manually before submitting

## Areas for Contribution

- Additional notification channels
- Native Windows support (PowerShell)
- More recovery strategies
- Documentation improvements
- Testing infrastructure
